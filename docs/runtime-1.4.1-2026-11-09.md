# 运行与工作表现优化 1.4.1

2026-11-09，Windows x64 / AutoCAD 2024。当前修改同时包含 1.4.0 的五项绘图能力，功能实测见 [十组绘图测试](drawing-tests-1.4.0-2026-11-09.md)。

## 本轮修改

- 兼容服务对流式请求返回普通 JSON 时，直接使用该次结果，不再丢弃后重复请求。明确不支持流式的服务按地址与模型记忆兼容结果；认证错误不重复发送。
- SSE 输出的截断、提前断开、服务端错误及非正常结束会停止执行，也不在已有部分回答后悄悄重试。正常的 finish_reason=stop 可完成没有 DONE 标记的流。
- 聊天预览以 100 ms 为刷新间隔，最多每秒 10 次；不再每个片段排队一次 Dispatcher。看到绘图代码围栏后停止收集计划预览；普通预览最多 8000 字符，完整回答仍在请求客户端校验。请求结束时停止定时器，空闲不轮询。
- 取消和超时显示对应结果，不再统一误报为密钥或网络问题。
- 空白模型空间首次生成很小的图形时自动放大到可见范围；已有图纸中的可见新增对象保持用户视图。检查模型空间是否为空只读取首个对象，不扫描整个大图。
- 原生 PDF 导出补足宽多段线边界，合并预览前消除页面旋转，避免圆盘边缘裁切和标题方向错误。

## 实际验证

| 检查 | 结果 |
| --- | --- |
| 纯逻辑、本地 HTTP、参数兼容及预览回归 | 152 项通过 |
| 原生 CAD 几何、单位、标注、填充、回滚检查 | 42 项通过 |
| 十万图元、大图视图和首图可见性 | 7 项通过 |
| WPF 面板 | 状态渲染、40 条消息预算、默认关闭统计及后台冻结缩略图通过 |
| PDF worker | 2 项通过 |
| 真实 auto 流式请求 | 角度与圆环两组均生成有效计划并落图，6/6 项选定 DXF 检查通过 |

十万图元模型中的上下文抽样耗时为 11/1/1 ms（三次）。本次可见新增圆约 3 ms，离屏且旋转视图定位约 340 ms；400 条原生命令批处理约 46 ms。这些是本机固定样本，不包含模型等待时间，不代表鼠标帧率或所有机器的性能。

真实 auto 流式角度任务约 35.788 秒，圆环任务约 13.431 秒，分别收到 687 和 507 个内容字符；完整请求与执行证据位于本地 `artifacts/runtime-auto-1.4.1/`。耗时受服务端路由和负载影响，不以两个样本宣称整体加速比例。单次 JSON 响应不会重复请求、流式错误不会重复消费的结论由本地 HTTP 请求计数回归验证。

首次小圆和宽圆环的视图可见性均在原生宿主检验；已有十万图元图形中的可见对象不改变原视图，离屏对象保留旋转角并正确居中。大图证据在本地 `artifacts/large-drawing/runtime-1_4_1.json`。

本机编译成功，但仍有缺少 .NET Framework 4.8 Targeting Pack 的现有 MSB3644 警告，采用 GAC 引用；以上原生测试在实际 AutoCAD 宿主完成。图元与计划一致不代表所有图片已被正确理解，先前赛题 auto 样本的识别偏差仍保留。

## 复验

`tools/Test-Runtime.ps1` 运行本地回归、原生 CAD、大图、WPF、PDF 和预览检查；添加 `-LiveModel` 才调用已有配置的 auto 发起两组真实模型请求。真实请求使用所配置服务的额度，配置与密钥不写入报告。CoreConsole 顺序执行并使用独立配置。

首次使用时，缺少 WPF 的 PDF 元数据会生成合成矩形与混合页作为测试附件。图纸预览仅在本地存在四组 DWG 时执行；可用 `-DrawingSuiteDirectory` 指定题组目录，缺少图纸时明确跳过可选预览，不依赖仓库外的私有赛题文件。

安装新版后保存图纸、重启 AutoCAD，输入 `AI`。当前运行窗口中的旧 .NET DLL 不会自动卸载替换。
