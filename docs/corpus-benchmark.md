# 插件 AI 赛题复刻评测

入口 `tools/benchmark_corpus.py` 将本地源题、插件的实际模型请求、锁定 DLL 的 AutoCAD 原生执行、选定来源核对串联。每次命令创建新的运行目录，不从旧计划推断新请求成功。原始资料、模型响应和生成图纸均留本地。

## 运行

```powershell
python -m pip install -r requirements-benchmark.txt
# 只渲染，不请求模型，也不启动 CAD
python tools/benchmark_corpus.py --prepare-only
# 检查本机能否原生落图，不请求模型
python tools/benchmark_corpus.py --preflight-only --case sixth-section33
# 已配置的插件 auto；每类连续保留三次尝试
python tools/benchmark_corpus.py --model auto --trials 3 --output artifacts/corpus-1.5.0
# 与面板“精细分块”相同的输入路径；是另一组实验，不与单图模式混记
python tools/benchmark_corpus.py --model auto --case sixth-section33 --detailed-images
```

默认题库为 `D:\AutoCAD 2024\高教杯水利赛道`，可用 `--source-root` 更改；文件必须位于该目录内。默认第五届整图、第六届3-3断面、第七届扭面大样三类。每轮按相同顺序执行，每次请求仍遵守插件的图片240秒总预算及至多一次计划修正，不自动修改配置、换模型或增加请求预算。

`auto` 只是配置的模型 ID。原始响应中的 `model` 即使也为 `auto`，仍不能确认底层模型或供应商；记录服务声明与配置哈希，不冒充独立身份验证。响应里的 usage 是服务报告值，不是账户余额或收费凭据。

## 如何读结果

`report.json` 区分请求成功、原生执行成功、选定来源检查通过。失败也立即写入独立 `trial.json`，总表按配置身份分别汇总全部尝试及耗时范围，不挑最佳结果。不把错误或缺失数据记作零耗时；混凝土等文字任务与图片赛题不混算通过率。

- 源题 PDF、裁图及提示分别保存哈希。锁定 DLL 和模型调用器源码，记录原生脚本及辅助程序源码身份；变更构建输出不会让后续轮次偷偷使用另一 DLL。
- 付费请求前先执行一份独立圆形探针并回读真实 DXF；环境或许可失败时，在调用模型前停止。Windows PowerShell 子进程自行构建模块路径，避免继承其他 PowerShell 版本的模块目录；不改变用户全局环境。
- 模型 HTTP 原始响应由显式诊断观察器保存，包括预检失败前的初始回答及自动修正回答。普通面板不启用这种响应落盘。每份响应保存哈希，不复制模型密钥或请求认证头。
- 每个原生执行使用独立输出目录及 `/isolate` 配置，核对 DLL/计划/辅助源码哈希，不接受零对象成果或异常退出后的残留产物。
- 阶段状态 `completed` 只代表评测流程结束；仍须看每次的 `selected_checks_passed`。退出码1可表示真实模型/来源核对失败，而非工具必定损坏。`prepare_only`、`preflight_only` 不产生 AI 成绩。

## 检查覆盖范围

| 样本 | 可自动核对 | 尚不能据此证明 |
| --- | --- | --- |
| 第五届整图 | 源图核读的11个数字（含重复读数）与原生尺寸测量值、毫米单位 | 每条尺寸所在视图、端点位置、扭曲面真实形状、全部材料纹理及像素 |
| 第六届3-3 | 14项选定检查：实际矩形轮廓、壁厚/内孔、四尺寸端点、中心线、图名、纹理及真实孔洞 | 字形、全部线距和像素相同 |
| 第七届扭面大样 | 已核读13个数字的原生测量多重集、毫米单位；模糊中部小字不计为正确 | 尺寸对应位置、扭面几何、未知文字、完整外观 |

所有报告继续保持 `source_accuracy_verified=false`。第五/七届的数字匹配不能代替完整几何核对；需要原生 PDF 视觉复核，再补充有来源依据的几何检查。

## 第六届检查器版本化

旧检查仅凭轮廓包围盒、填充环数量，可能误将菱形、交叉四边形或错位孔洞记为正确。v2要求真实直边矩形，拒绝圆弧边和交叉轮廓；尺寸端点须在真实边上，中心线须贯穿截面，填充边界须与实际外环/内孔一致，忽略岛屿的填充不能证明空孔存在。支持实际水平/竖直对齐尺寸及 TEXT/MTEXT 图名。

具有一个内孔时，Normal 与 Outer 均可保留该孔；Ignore 会填过内孔，因此不能把它计为正确。这一判断依照 [Autodesk HatchStyle 定义](https://help.autodesk.com/cloudhelp/2026/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_DatabaseServices_HatchStyle.html)。

检查器版本及哈希进入报告。旧 v1 的9/14分数不能直接与 v2比较为“提高/下降”；应对同一旧 DXF 使用新检查器重算，再和新图作同标准对照。生成的反例测试只验证检查器，不算 AI 复刻成绩。

v3进一步修正合法的开放两顶点直线多段线下划线被漏认的问题；不把原生实体类型不同当成源图外观错误。可用 `python tools/recheck_corpus.py <运行目录>` 对未被修改的原DXF补充复核，不覆盖原报告、不发起新AI请求；源DXF或原计划哈希改变时拒绝复核。
